## Как устроено хранение — без новых сущностей

Цвет лежит в **ТОЙ ЖЕ записи**, что и позиция знака: `zoneOverrides[formId][brandKey].color`.

Почему так, а не отдельным файлом: редактор уже умеет сохранять эту карту, отдельный файл
потребовал бы **второго эндпоинта в mu-плагине**. Соседство безопасно по конструкции —
`validateOverrides` терпит лишние ключи (проверяет лишь, что `x,y,w,h` числа), а `resolveBrandBox`
берёт только четыре координаты и на `color` не смотрит.

## 🔴 Три места, где легко наступить снова

1. **Серверный белый список молча съедает новые поля.** `deploy/jetron-zones.php` пересобирал
   запись из `x,y,w,h` и выбрасывал всё остальное. Фронтовая правка без серверной работала бы
   локально и **исчезала на боевом** при сохранении. Пропуск цвета добавлен строгой регуляркой
   `^#[0-9a-fA-F]{6}$` — граница остаётся закрытой, но для цвета есть дверь.
2. **Редактор заменяет запись знака ЦЕЛИКОМ** (`session[fid][brandKey] = box`). Админ выбирает
   цвет, потом двигает знак мышью — и цвет **молча стирается**. Лечит `brandEntryFromBox(prev, box)`:
   она переносит цвет из прежней записи. Сторож — тест «перетаскивание не стирает цвет».
3. **`deploy/` едет на боевой ТОЛЬКО руками** через WP File Manager, git его не выкладывает.
   Пока `jetron-zones.php` не выложен, на боевом цвет выберется, покажется и пропадёт после
   перезагрузки — **молча**. Обратная сторона: мерж PR физически не может уронить сайт битым PHP.
   ⚠️ `php -l` не выполнялся, интерпретатора на машине нет и winget пакета не нашёл. Сделана только
   сверка балансировки (73/73 фигурных, 248/248 круглых, кавычки чётно) и перечитан блок. **Это
   честный долг: PHP непролинтован.**

## Перекраска — одна операция, а не SVG и не 30 файлов

🔴 **Explore-агент выдал ложное «главное препятствие»:** будто PNG перекрасить нельзя, нужен SVG,
canvas-фильтры «сложно», а 30 файлов «неприемлемо». Опровергнуто **замером Pillow**, а не спором:
знак 779×311, 242 269 пикселей, из них **109 283 непрозрачных, полупрозрачных 0**, и вся
непрозрачная часть — РОВНО ОДИН цвет. Плоский силуэт с жёсткой альфой.

Отсюда перекраска = `drawImage` → `globalCompositeOperation = 'source-in'` → `fillRect`, результат
кэшируется по цвету в `Map`. Отсутствие полупрозрачных пикселей означает отсутствие цветной каймы
на краях — это и была единственная реальная опасность метода.

**Регрессия 45 расцветок исключена по конструкции:** `источникЗнака()` отдаёт для `#ffffff` и
`#111111` ГОТОВЫЕ файлы (`перекрасить: null`), перекраска включается только для остальных цветов.
