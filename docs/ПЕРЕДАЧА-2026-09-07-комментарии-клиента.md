## п. 5 — кнопка «в карточку» (ЗАКРЫТ, читать до правок в этой области)

Замер боевого дал три факта:
- все восемь адресов `/product-category/<линейка>/` отдают **404** — раздела каталога по линейке
  на сайте нет вовсе, запасной путь вёл в никуда. Это и была жалоба клиента.
- каталог жив: 91 позиция, у всех непустой `url`.
- пар «линейка+цвет+возраст» 90, совпадало **66**; после таблиц замен в `CatalogPrices.js` — **81**.
  Оставшиеся 9 в WooCommerce физически отсутствуют (взрослый Champion целиком = 6, взрослый
  Фаворит Белый/Синий/Красный = 3). Товара нет — адреса взять неоткуда.

Решение: **нет адреса карточки → кнопки нет вовсе**. `productLink()` возвращает `null`,
второй параметр `catalog` из сигнатуры удалён (тесты его ещё передают — безвредный хвост).

🔴 **Ловушка, пойманная чтением, а не тестом:** в `_renderLineBadge()` было
`if (!line || !link) { badge.remove(); return; }` — с отменой запасного пути это унесло бы
у 9 пар из 90 вместе с плашкой кнопку **«Скачать макет»**, к ссылке отношения не имеющую.
Теперь плашка держится на `line`, третья пилюля рисуется только при `link`.

Живая приёмка (headless, локальный сервер 8778): ПК 1366×768 — детей 2, центр плашки 512,
центр «Скачать макет» 512, `.line-badge-cta` = 0; телефон 390×844 — 195 и 195, `.line-badge-cta` = 0.
Grid `1fr auto 1fr` держит центр без третьего ребёнка (третья колонка существует и пустой).
Скрипт замера — `C:\tmp\jm\badge.mjs`.

(GitHub Pages, каталога нет) кнопки теперь не будет вовсе. Оговорка из письма №13 больше неверна.

## п. 6 (+ п. 4) — цвет свотча (СДЕЛАН В КОДЕ, на боевом не проверен)

Дословно клиент: «эта форма у неё в атрибуте стоит цвет жёлтый, а в конструкторе она почему-то
под зелёным цветом показывается» и «салатовый… по факту это не салатовый, это какой-то
грязно-зелёный. Я в админке зашёл и цвет салатовый поменял на ярко-салатовый… но в конструкторе
квадратик не поменялся. Можете связку сделать или сказать, как правильно его поменять».

Собрано чтением кода:
1. Свотчи рисует `buildColorPicker()` (`app.browser.js:534-571`) из `this.config.colors[].hex`.
   Палитра — полный список; при клике меняется только `.active` (перерисовка сбрасывала `scrollLeft`).
2. Связка «админка → палитра» **уже есть**: `AdminOverrides.js` подменяет `out.colors` из `admin.json`
   (`listOr` + `isColor`), пустой список = «не трогай», а не «удали всё».
3. 🔴 **Причина жалобы найдена в `deploy/jetron-admin.php`:**
   ```php
   if (!$has_color) { $colors[] = array('id'=>$color_id, 'name'=>$color, 'hex'=>$hex); }
   ```
   форма «Модели и цвета» дописывает цвет, **только если такого `id` ещё нет** — hex уже
   существующей расцветки через неё поменять НЕЛЬЗЯ. Правки цвета в плагине не было **ни одной**:
   действий всего семь (`prices`, `sizes`, `font_add`, `font_del`, `model_add`, `model_del`,
   `reset`), и оттенок заведённой расцветки был из админки недостижим в принципе.
   ⚠️ Это причина по коду, замером боевого НЕ подтверждена — клиент мог менять цвет и в
   WooCommerce (`pa_color`), а туда наша палитра не смотрит, см. п. 4 ниже.
4. hex из WooCommerce взять неоткуда: у терминов `pa_color` нет ни hex, ни свотч-меты
   (замер 30.07, записан комментарием в `jetron-admin.php:691-697`; там же — почему цвет берут
   с загружаемого фото самым частым пикселем).
5. Базовая палитра `src/config/mock-config.json`, 15 цветов; к жалобам относятся
   `green #1a9c5b`, `lightgreen #8bc34a`, `lime #a4c639`, `yellow #ffd400`.

**Сделано 07.09 (связка замкнута с обеих сторон):**

- `deploy/jetron-admin.php` — новое действие `colors` и таблица «Цвета кружков в фильтре»
  на вкладке моделей: по одному `<input type="color" name="hex[<id>]">` на расцветку.
  Меняется ТОЛЬКО оттенок; названия, модели и фотографии не трогаются. Мусор отсеивает
  `sanitize_hex_color`, ничего не изменилось — файл не переписывается вовсе.
- Там же кружок в таблице каталога перенаправлен на палитру (`$palette[$colorId]`), иначе
  админ видел бы один оттенок в своей таблице и другой у покупателя.
- `src/js/core/OrderSummary.js` — 🔴 **вторая точка, которую легко проглядеть:** кружок «Модель»
  в сводке заказа брал `form.colorHex`, то есть СНИМОК оттенка на момент заведения модели.
  Поправь только палитру — свотч бы обновился, а кружок в корзине нет, и клиент пожаловался бы
  второй раз. Теперь оттенок ищется в палитре по `colorId`, снимок остаётся запасным путём
  (нет расцветки с таким id — кружок не должен пропасть).
- Та же связка в PHP: если `admin.json` уже переопределяет `forms`, снимки `colorHex` внутри
  догоняют палитру. Если не переопределяет — не трогаем, иначе в `admin.json` лёг бы весь
  каталог форм, которого там не было.

Доказательства (реализация без предварительного красного не проходит `tdd-guard`):

## п. 7 — сохранение настроек между перезагрузками (СДЕЛАН И ПРОМЕРЕН НА ЖИВОМ)

раз, ходит, заходит в корзину». Отсюда **TTL 24 часа** и обязанность пережить корзину.

🔴 **Опровергнута моя же запись «логотипы живут как blob URL».** Так вёл себя только ЛЁГКИЙ путь
`prepareImage()` (файл до 1,5 МБ вставлялся `URL.createObjectURL`); тяжёлый уже отдавал data:
через `canvas.toDataURL`. Лёгкий переведён на `FileReader.readAsDataURL` — **байты не трогаем**,
пережатие в jpeg убило бы прозрачный фон логотипа. Сторожит `tests/DraftWiring.test.js`.

🔴 **Три места, где легко сломать обратно:**
- **Флаг `_draftReady`.** `updatePrice()` зовётся ещё и из `renderAll()`, то есть ДО восстановления.
  Без флага первая же отрисовка пустого конструктора затёрла бы хорошую запись прошлого захода.
  Флаг ставится последней строкой `_restoreDraft()`, `_saveDraft()` без него молча выходит.
- **Порядок в `start()`:** `_restoreDraft()` → `buildPanel()` (панель рисуется из состояния, иначе
  покупатель увидит «Взрослая» при восстановленной детской и нажатием обнулит себе выбор)
  → `renderAll()` → `_applyRestoredOptions()` (наносить опции можно только на готовые холсты).
- **`clearDraft` намеренно НЕ импортируется** в `app.browser.js`. Клиент просил обратного —
  черновик обязан пережить корзину и оформление, умирает он сам по сроку.

📌 **Размер намеренно НЕ сохраняем:** сетка зависит от каталога и возраста, вчерашний размер
сегодня может отсутствовать — покупатель увидел бы пустой выбор при заполненной цене.
📌 **`sanitizeDraft` выбрасывает всё, чего нет в СЕГОДНЯШНЕМ конфиге** (клиент сам снял
`champion-sinij3` 31.08): иначе нарисуем форму, которой нет в продаже, и назовём за неё цену.
Цвет берётся из конфига по `formId`, а не из черновика — пара «форма+цвет» неразрывна.

- четыре ТЯЖЁЛЫХ логотипа (по 4,6 МБ в кэше) → лестница сброса отработала: остальные настройки
