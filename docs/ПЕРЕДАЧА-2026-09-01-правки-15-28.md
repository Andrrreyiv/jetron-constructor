### Пункт 1 — верхняя полоса 216 → 100 → 60 px

Самое объёмное. `TOP_PX` в `scripts/normalize_mockups.py` = **60**, рядом
`СДВИГ_ФОРМЫ = 216 - TOP_PX` = **156**.

🔴 **Главная механика, не потерять:** кадр укоротился **СВЕРХУ**. Историческая формула
пересчёта зон `y_new = y_old × 1200 / H` верна только когда кадр меняется СНИЗУ. При срезе
верхней полосы форма ПОДНИМАЕТСЯ на `сдвиг`, поэтому:

```
y_new = (y_old × 1200 − сдвиг) / H_new
h_new =  h_old × 1200 / H_new          # h делится, но НЕ сдвигается
```

Что сделано под это:
- `наборы_зон(шаблон, кадры, эталон, сдвиг=0)` — параметр `сдвиг` добавлен.
- `расставить_наборы(config, кадры, сдвиг=СДВИГ_ФОРМЫ)` — **по умолчанию берёт число
  из нормализатора**, а не ноль. Это единственная боевая точка входа; раньше забыть
  сдвиг можно было молча, и все зоны уехали бы на срезанную полосу.
- Перегнаны все **45** мокапов: `прогнано 45, битых 0, нарушений 0`.
  Кадры ровно на 156 короче: Champion 992→**836**, Legend 1006→**850**, Фаворит 1025→**869**,
  Winner 1027→**871**, Волна 1031→**875**, Space 1035→**879**, New 1093→**937**, Star 1110→**954**.
- `РАМКИ_НАШИ` в `scripts/rewrite_catalog.py` **перемерены**, а не пересчитаны на бумаге:
  маска «отличие от белого > 15» (тот же порог, что 30.08) дала
  `front (0, 60, 417, 777)`, `back (481, 61, 899, 777)` в кадре `(900, 836)`.
- `zoneSets` в `src/config/mock-config.json` и корневой `zones.json` пересчитаны.
  Контроль: абсолютная строка каждой зоны уехала на **−156 px**, максимальное отклонение
  **0.096 px** (округление до 4 знаков). Все 11 зон `champion-white` остались внутри

- `ВЫСОТА_ПЛАШКИ` в `tests/test_normalize_mockups.py`: **65 → 32**. Прежние 65 были
  ОЦЕНКОЙ под кадр 900×1200 и устарели молча, когда кадр укоротился.

⚠️ **Почему 60 — это пол, а не вкус.** Замер headless 1366×768, все восемь линеек:

```

Legend   850 → 27.9      Волна  875 → 28.8   Star 954 → 31.4  ← худшая
```

### Пункт 7 — кнопку «в карточку» в правый верхний угол

Клиент: «перейти в карточку, так же нужно приклеить к правому верхнему углу».

**Что показал замер (360×640):**
- `.line-badge` = ряд x 12, ширина **336**, три пилюли, `grid-template-columns: 1fr auto 1fr`,
  `gap: 8`. У `.line-badge-cta` уже стоит `justify-self: end`.
- Кнопка: x 203.1, ширина **90.9**, высота **68** — то есть текст ломается на **ТРИ**
  строки: «В» / «КАРТОЧКУ» / «→». Это и есть то, что клиент видит.
- Правый край кнопки **294**, крестик закрытия — `position: fixed`, x **306..350**
  (44 px + отступ 10). Между ними 12 px.
- На мобиле действует `@media (max-width: 900px)`: `.line-badge { padding-right: 0 }`
  и `.line-badge-cta { margin-right: 54px }` — **54 px это ровно след крестика**,
  зазор заведён 28.08 после замера перекрытия 42×19 px.

🔴 **Конфликт был не в ширине, а в том, что угол ЗАНЯТ крестиком.** Просто снести
`margin-right: 54px` нельзя — кнопка уедет под крестик и станет некликабельной
(крестик несёт `z-index: 2147483647`, нажатие уходит ему, а он выкидывает из конструктора).

🟢 **Как решено: развели не по горизонтали, а по ВЕРТИКАЛИ.** Крестик стоит
`fixed top: 10` высотой 44 → низ на y = 54. Ряд плашки стоит от верха `.views`, а это
y = 35 на ЛЮБОЙ узкой ширине (отступы `#app` и `#stage` там константы, проверено на
четырёх ширинах). Значит достаточно опустить весь ряд на 20 px — и правая пилюля
встаёт вплотную к правому краю картинки, в тот самый угол, не пересекаясь с крестиком.

```
.line-badge     { padding-right: 0; top: 20px; gap: 6px; }   /* было gap 8, top 0 */
.line-badge-cta { margin-right: 0; }                          /* было 54px */
```

**Вторая половина — перенос строки.** Он держался на мобильных размерах пилюли:
клиент 31.08 просил «все эти кнопочки уменьшить, процентов на 20», и правку тогда
получил только ПК (`padding: 5px 11px`, кегль 10.5) — блок `@media (pointer: coarse)`
перебивал её обратно на `44 / 12px 14px`. Возвращено: `min-height: 36`, `padding: 7px 8px`.

⚠️ **Считать надо не сумму трёх пилюль.** В сетке `1fr auto 1fr` правая колонка ВСЕГДА
равна левой, то есть `(ряд − зазоры − середина) / 2`, и лишняя ширина уходит короткому
ярлыку линейки впустую. Из-за этого на 360 px колонка давала 103.05 при нужных 105 —
кнопка срывалась во вторую строку из-за 1.9 px. `gap` 8 → 6 дал 106.05.

На 320 px этого не хватает (колонка 90.5 при нужных 94.9), поэтому в конце файла
добавлен `@media (max-width: 340px) { .line-badge-pill { font-size: 9.5px; padding: 7px 6px } }`.
⚠️ Он стоит ПОСЛЕ блока `pointer: coarse` намеренно: специфичность одинаковая (0,1,0),
решает порядок в файле — внутри `max-width: 900px` это правило молча проигрывало,
`padding` оставался 8 px (замер это и показал: числа не изменились ни на пиксель).

**Контрольный замер после правки** — везде одна строка, кнопка вплотную к краю,
перекрытия с крестиком нет:

### Пункт 8 — рамка активного цвета залезает на бегунок

Клиент: «когда рамка появляется синее, она на бегунок залезает. Надо чтобы бегунок
чуть-чуть вниз опустить, либо вот сами цвета сделать меньше… процентов на 20 точно».

**Что показал замер (360×640) — жалоба воспроизводится точно:**
- `.colorpick .color-palette` на мобиле: `overflow-x: auto`, `clientW 342` против
  `scrollW 470` → **палитра прокручивается, бегунок есть**.
- `padding: 5px`, свотч 26 px → низ свотча на 31, высота бокса **36**.
- Кольцо активного цвета: `box-shadow: #fff 0 0 0 2px, #2f6fe4 0 0 0 4.5px` → тянется
  до **35.5**, то есть до самой нижней кромки бокса, где и рисуется оверлейный бегунок.
  **Просвет 0.5 px.** Это ровно то, на что он жалуется.

🔴 **ПОБОЧНЫЙ ДЕФЕКТ, который я внёс пунктом 2.** Правило
`.colorpick .pcolor { width: 26px }` (специфичность 0,2,0) **перебивало** мобильные
`@media (max-width: 900px) .pcolor { width: 40px }` и
`@media (pointer: coarse) .pcolor { width: 44px }` (обе 0,1,0) — медиазапрос
специфичность не повышает. На телефоне свотчи стали 26 px вместо 40, тач-цель просела
ниже нормы, а `gap` заодно упал с 11 до 5. **Это тот же класс ошибки, что и в пункте 7
с `padding` на 320 px** — оба раза правило молча проигрывало, и оба раза это увидел
только замер, а не чтение кода. 📌 Запомнить: медиазапрос НЕ повышает специфичность.

🟢 **Как решено (три правки, все проверены замером):**

1. Колоночные правила палитры завёрнуты в `@media (min-width: 901px)`. Раскладки
   «палитра сбоку» ниже 901 px просто нет, так что правило описывает ровно свой случай.
   На ПК всё осталось как требовал клиент: одна колонка, свотч 26 px, `gap` 5,
   высота блока 470 при доступном 491.
2. Мобильный размер по просьбе клиента −20 %: `max-width: 560px` 40 → **32**,
   `pointer: coarse` 44 → **36**. ⚠️ 36 — это осознанный отход от минимума 44 px (iOS HIG),
   а не недосмотр: клиент попросил обратное, и назад без его слова возвращать нельзя.
   Промахов не прибавится — свотчи стоят в ряд с зазором 11 px.
3. Мобильной `.colorpick .color-palette` дан `padding: 5px 5px 14px` вместо 5 по кругу:
   кольцо 4.5 + бегунок ~7 + просвет 2.5. Клиент сам предложил оба пути («бегунок вниз
   опустить, либо цвета меньше») — сделаны оба, они не спорят.

**Замер после правки (360×640):** свотч **36**, `gap` **11**, высота бокса **55**,
кольцо доходит до **45.5** → чистых **9.5 px** до кромки, где рисуется бегунок
(было 0.5). Жалоба закрыта с запасом.
